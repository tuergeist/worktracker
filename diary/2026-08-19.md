# 2026-08-19

## Pläne: empty-save guard, content clarity, trend charts

Continuation of the Pläne feedback loop from 2026-08-18 (still all local, not yet committed/pushed — see that diary for the full history of the feature and the earlier rounds of UI correction).

### Changes Made

**Content fixes** (`frontend/js/plans.js`):
- Range's "Wind / Platz heute" moved from block 2 (Teildistanzen) to block 1 (Aufwärmen) — mirrors the earlier "Grün heute" placement decision for Kurzspiel (asked once at the start, not mid-flow).
- "Teildistanzen · 50 m" block was confusing on two counts, both raised by the user from real usage: the description mentioned practicing at 8/9/10 Uhr swing lengths but only asked for the 9 Uhr value (now explicit: "8 und 10 Uhr dienen als Kalibrierpunkte drumherum"), and "Auf 50 m ±5 m" never explained what the number meant (now: "10 Bälle aufs 50-m-Ziel — wie viele landen im Fenster 45–55 m?", field label renamed to "Treffer im Fenster 45–55 m").

**Empty-run guard**: `saveRun()` now checks `hasAnyData()` before posting — if every field is still at its untouched default (null/empty/0), it blocks the save (haptic warning + `alert()`) instead of writing a blank history card. Triggered by a real example: a fully-empty Range run on the live site with nothing but a date. Note the inherent tradeoff: count/greenScale fields use `0` as their "unselected" sentinel, so a run where every recorded value is genuinely 0 also gets blocked — accepted as correct behavior since an all-zero accidental-tap run and an all-zero intentional-report run are indistinguishable from stored state alone, and the former is far more common.

**Trend charts** (new, scoped via two AskUserQuestion rounds with the user): Statistik → Pläne now has a metric chip row (reuses `.club-strip`/`.club-row`/`.club-chip` — same "pick one, see its trend" pattern Range already uses for clubs) above the history-card list, showing one `lineChart()` (existing `chart.js`, zero new charting code) for whichever numeric field is selected. Scoped to genuine distance/count fields only (`chartableFields()` filters to types `number`/`count`/`gap`) — excludes the green-speed scale, free text, and notes. `local.plansRuns` caches the last fetch so switching the selected metric re-renders instantly without a network round-trip. `index.html` gained `#plans-metric-row` + `#plans-chart` in the Pläne stats pane.

Empty-save guard tested both ways: blank step 7 → blocked, stays on step 7, no confirmation screen; same step with one field filled → saves normally. No console errors throughout. All test/backdated runs deleted afterward.
